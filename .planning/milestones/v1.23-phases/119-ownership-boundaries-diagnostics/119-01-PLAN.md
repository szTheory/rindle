<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Host/application configuration to snapshot | Prefix and repo configuration is untrusted until checked against fixed supported authorities. |
| Snapshot to PostgreSQL catalogs | Read-only catalog queries must remain allowlisted, bound, and permission-aware. |
| Diagnostic data to operator output | Database failure details must be reduced to stable non-sensitive classifications and actions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-119-01 | Tampering / Elevation | `OwnershipSnapshot` identifier handling | high | mitigate | Admit only fixed Rindle prefixes and relation allowlist; bind catalog values and quote only validated identifiers; prove malicious/invalid prefix refusal before SQL. |
| T-119-02 | Denial of Service | catalog and permission failures | medium | mitigate | Preserve query/permission errors as `:inspection_failed`; never reinterpret an unavailable catalog as a missing install or migration recommendation. |
| T-119-03 | Information Disclosure | doctor check data and text | high | mitigate | Drop raw adapter reasons at the snapshot boundary; render fixed fields and assert sentinel SQL/Postgrex/credential strings are absent. |
| T-119-04 | Tampering | host `oban_jobs` and ledger | high | mitigate | Snapshot is query-only and excludes `schema_migrations`; no DDL/config calls are introduced and later integration proof snapshots host state before/after. |
| T-119-SC | Tampering | package installs | high | mitigate | No package install is planned; if execution introduces one, stop for a Package Legitimacy Audit and slopcheck gate. |
</threat_model>
