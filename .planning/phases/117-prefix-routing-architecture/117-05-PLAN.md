<interfaces>
From installed Ecto 3.13.5 in `deps/ecto/lib/ecto/schema.ex`:
- `Ecto.Schema.__using__/1` imports the public `schema/2` macro and registers mutable caller-module attributes.
- `Ecto.Schema.schema/2` delegates to `Ecto.Schema.__schema__/5`, which reads `Module.get_attribute(module, :schema_prefix)` and embeds that value into both `__schema__(:prefix)` and the struct's `Ecto.Schema.Metadata`.
- Excluding an import affects only unqualified lookup; any caller can still `require Ecto.Schema` and invoke `Ecto.Schema.schema/2` remotely. A wrapper or consumer-owned compile callback therefore cannot provide an absolute boundary for arbitrary modules.

From the shipped Rindle boundary:
- `Rindle.Schema` is already hidden with `@moduledoc false`, and its macro/functions are hidden with `@doc false`; it is an internal schema implementation seam, not a documented adopter extension point.
- Exactly six library-owned modules use it: `Rindle.Domain.MediaAsset`, `MediaAttachment`, `MediaProcessingRun`, `MediaProviderAsset`, `MediaUploadSession`, and `MediaVariant`.
- The owned-source AST contract already rejects direct `use Ecto.Schema`, direct Ecto imports, remote `Ecto.Schema.schema/2`, and direct `@schema_prefix` writes in those six files.
- `config/test.exs` compiles the explicit `public` compatibility posture; `MIX_ENV=dev` with no override compiles the default `rindle` posture.
</interfaces>
