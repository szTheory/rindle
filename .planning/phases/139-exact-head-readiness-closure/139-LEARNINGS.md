# Readiness liveness lessons

These are execution lessons from Phase 139. Requirement credit still depends on
the terminal verdict and its retained evidence.

| Decision | Lesson and retained control |
|---|---|
| Separate source qualification, scheduled operations and mutable authority | A fixed source can use a complete same-source Nightly dispatch. Incident recovery requires a genuine scheduled run under matching controls. Security, inbox, protection and adoption observations must remain fresh. |
| Separate schedule deadlines from evidence freshness | Require creation by the daily 07:27 UTC slot plus 60 minutes and completion within 120 minutes of actual creation. A healthy completed run covers that slot; 120 minutes is not an evidence age limit. A newer pending or failed run, changed controls, unavailable journal or expired artifacts still reject. Compatible main advancement does not require another scheduled run. |
| Freeze the candidate while main advances | Authenticate protected-main ancestry and executing policy bytes, then preserve the checkout. Later bookkeeping names the accepted SHA, interval and terminal locator as historical evidence. |
| Compare fresh mutable observations after native work | An hours-long collection is not a transaction across services. Keep the early preflight, then compare two complete observations after qualification. Drift within that pair still rejects. PR209 retains the whole signed registry identity. |
| Hash decision inputs | PR208 excludes only repository size from PR decision identity. Preserve the raw authenticated responses and every other known or unknown field; do not broadly remove timestamps or mutable facts. |
| Distinguish synthetic merge commits from reviewed changes | GitHub can regenerate an open PR test merge during a GET. Retained reads of PR187 changed only test-merge SHA and repository size while its head, base and mergeability stayed identical. Exclude test-merge SHA only for explicitly open, unmerged PRs; keep actual merged commits and every other field significant. |
| Retain failure evidence before runner cleanup | A late PR comparison failure on producer40648108188/1 left no uploaded graph. A separate diagnostic exporter retains only byte-checked native graph objects and fixed failure metadata after a secret scan, with no READY credit. Failed-run status and normal acceptance artifact identities stay unchanged. |
| Build API fixtures from primary schemas | PR201 corrected the documented `vulnerability_alerts` permission key. A successful private GET did not justify broader credentials. Missing or forbidden visibility remains unavailable. |
| Distinguish transport consistency from authority | PR202 and PR207 reacquire inconsistent inventories or pinned files within finite budgets. Revalidate full pagination, unique IDs and pinned Git blob bytes. An incomplete response never means an empty inventory. |
| Preserve remote work when local observation fails | The original BB controller failed with `remote_unavailable` while producer 40609107572/1 continued. Preserve the failed terminal and reconcile its nonce, run and attempt before dispatching anything. An audited continuation may adapt only the completed dispatch, nonce and remaining budget; it retains the original checks and verdict writer. |
| Exercise complete host inventories before expensive work | Run collection exhausted 180 seconds after 91 successful GETs; remote collection exhausted 600 seconds after 455 GETs during its second Hex audit. PR211 uses finite 360/1200-second acquisition windows and a 30-second caller shutdown allowance. Full pagination, both observations, signed root/demo audits, call caps and eligibility remain required. Test success beyond the old bounds and rejection beyond the new bounds, then run actual complete host preflights before qualification. |
| Record attempts before parsing responses | The old transport lost diagnostics for headerless failures because it recorded only parsed HTTP responses and discarded stderr. Future observability work should record bounded attempt start/end and a safe error identity even when no headers arrive. Keep private payloads restricted. Never manufacture success or silently retry a write. |
| Preserve uncertainty | The exact hosted field behind earlier drift was not retained. Separate local reproductions from a proven hosted cause. The BB polling failure also lacks an exact transport cause because stderr was discarded. |
| Separate progress from acceptance | A successful poll proves observation is alive. A running cloud step does not prove that individual gates or seeds passed. Future observability work should expose fixed, redacted phase/iteration signals; the retained graph remains the acceptance authority. |
| Keep one owner and an exit witness | A lost tool session does not establish process failure. A direct parent records controller exit. Keep registration, first terminal bytes and cloud identity together; never infer success from elapsed time or process disappearance. |
| Keep operator instructions consistent | Review the runbook and evidence guide together. A stale candidate-only scheduled prerequisite recreated the old wait in the guide after v3 separated qualification and health. Use the existing no-bytecode collector wrappers so preflights preserve the clean source. |
| Give fixtures their own metadata | Controller fixtures own their metadata root and invoke the real parity checker. Keep explicit hostile-root cases and a controller case with invalid owned metadata. Production parity stays unchanged. |
| Prefer small local changes | Reuse existing parsers, lockfiles, CI lanes and executable seams. No new runtime dependency was needed. Test-only policy workers retain fresh CLI parity, strict bounds and owned cleanup. |

The full 25-seed experiment remains required. Its cost is separate from the
deferred numeric CI speed target; qualification does not close CI-16. A transport
interruption must not silently trigger another full experiment.

Producer 40609107572/1 on
`bb0341a07ebf58b556aff4bcfa84003673d0151f` completed all 18 native commands.
They totaled 13890.542 seconds; the 25 seeded coverage executions took 11445.971
seconds. These measurements explain the cost, but that producer never obtained a
successful durable terminal acceptance. Its proof cannot transfer to a new source.

The temporary owner-only transport reduced selected connection latency but did
not complete acceptance. Its final continuation still exhausted the original
600-second remote deadline. All temporary services stopped and all 13 failed
controller terminals remain immutable. PR211 repairs the measured acquisition
budgets in the maintained collectors without a new dependency or transport service.
The changed controller bytes require a new admitted source and its own qualification.

Inspect historical evidence with the accepted source's verifier and runtime.
Removing the approved temporary recovery cron restores one exact workflow hash;
it does not create a permanent whitelist or grant readiness to a later head.
Independent Phoenix pilots, 1.0, publication and held PRs retain their separate gates.
