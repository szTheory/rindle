<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Default host Oban config to query routing | Repo and prefix values can redirect reads unless canonical instance, repo, and identifier constraints are enforced. |
| Catalog visibility to classifier | Permission-limited or failed reads must not be trusted as evidence of absence. |
| Diagnostic service to host-owned state | Read-only inspection must never become DDL, queue management, ledger access, or application configuration mutation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-119-05 | Tampering / Elevation | default Oban prefix resolver | high | mitigate | Require the default module, configured Rindle repo, and validated binary prefix; reject false/invalid/named/alternate-repo shapes before SQL. |
| T-119-06 | Denial of Service | catalog permission/query failure | medium | mitigate | Preserve `:inspection_failed`, assert no migration recommendation, and test both injected and live failure paths. |
| T-119-07 | Tampering | host relations and application env | high | mitigate | Snapshot relations/config before and after production diagnostic calls; fail on any DDL, data, or env mutation. |
| T-119-08 | Information Disclosure | classifier and telemetry | high | mitigate | Store only fixed classification/prefix fields and assert raw adapter/credential sentinels are absent. |
| T-119-SC | Tampering | package installs | high | mitigate | No install is planned; any newly proposed dependency requires a Package Legitimacy Audit, slopcheck, and blocking review. |
</threat_model>
