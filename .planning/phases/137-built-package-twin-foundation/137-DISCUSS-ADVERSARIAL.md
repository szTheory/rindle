## Integrated recommendation

Proceed with one dedicated minimal external Phoenix host and **one authoritative Docker/Compose execution path**. Reuse the repository's container/service conventions, not the Cohort application image or its checkout build context. The host receives only the fresh package archive/extracted package, explicitly selected host/fixture source, consumer lock, and declared configuration. No checkout, home directory, Docker socket, repository BEAM output, or inherited Mix build paths enter its runtime. Parent orchestration may read the checkout to build and stage those inputs. Compile the package and host into an empty run-owned build root. Run the verifier through the same isolated input boundary.

Use adopter-owned Repo, default Oban with normal queues, supported migrations, run-owned PostgreSQL/MinIO/temp resources, and a **tiny fixed host-owned PostgreSQL fault counter table**. The existing required database makes an atomic conditional decrement simpler to reason about than a new retained-file claim/reset protocol. Keep that table a fault specimen, not an event store or general journal. Match the run, delete operation, and exact synthetic object key; record configured and consumed counts separately.

The foundation tracer uploads one image, creates one ready variant, attaches with `Rindle.attach(asset_or_id, owner, slot)`, then issues one `Rindle.detach(owner, slot)`. Observe the same persisted purge job fail and become retryable at attempt one. Pause the local purge queue, confirm paused/no running jobs, and re-read the unchanged committed retryable row. Terminate the host container/BEAM, observe actual exit, then start a fresh runtime with the same database, fault state, artifact and temp resources. Let the existing job complete at attempt two under normal scheduling. Record the intentional pause and call this a **controlled between-attempt restart**. No new stimulus, private worker calls, scheduling writes, manual drains, or crash-rescue claim are needed.

One typed receipt validator using existing Jason checks identities and finite scenario predicates. Independent observations establish object/job/domain facts before teardown; disposal protects the environment without converting failed cleanup to success. Keep ordinary discuss → plan → execute → verify, at most six plans with at most three tasks each, and rescope after the same gate fails twice (`134-CONTEXT.md:26–30`). No additional framework, dependency, production API, frontend, or broad CI matrix follows from this review.

Read-only public schema use would not create a new seam. Prefer the existing facade for this bounded tracer:

## Should change / keep precise

- **Choose a counter table, not both counter backends.** Its cost is one host migration and a small atomic update; its benefit is committed state across BEAM replacement and concurrency using an already-required service. A retained-file backend would save one table but introduce claim-file persistence, crash and corruption rules that add no adopter value here. Do not generalize the table for future unknown scenarios.
- **Use container identity and observed exit, not PID inequality alone.** PIDs can be reused. `exec` the BEAM as the application process, use ordinary init/reaping where necessary, wait for container termination, then verify a fresh boot token and active queues. Docker stop is bounded TERM then KILL; a graceful stop still proves between-attempt runtime replacement, and does not prove an executing-job crash. [Docker stop](https://docs.docker.com/reference/cli/docker/container/stop). Preserve DB/fault/temp storage across replacement and keep restart configuration distinct from final disposal.
- **Make final inventory stable.** Stop new scenario inputs; let or explicitly quiesce outstanding jobs before listing. Object and multipart pagination must complete. Do not sample until one empty response happens to appear. A cleanup command returning zero in dry-run mode is not cleanup.
- **Allow only named bounded retained history.** Completed Oban rows and migration metadata can be approved evidence before DB disposal. A broad “all public tables allowed” rule hides work. Running/scheduled/retryable jobs remain unapproved after terminal cleanup. Generic catalog inventory must treat access/query failures as unknown.
- **Do not assert every object survives a failed purge.** The worker deletes variants before the original (`lib/rindle/workers/purge_storage.ex:27–40`). If the selected failure targets the original, earlier variant deletions are legitimate partial effects while the durable asset handle remains. Either target the sole ready variant key first or explicitly record partial effects. Do not encode a stronger invariant than shipped behavior.
- **Bind the consumer's actual lock/toolchain.** Root Oban is 2.21.1; Cohort is 2.23.1 (`mix.lock:49`; `examples/adoption_demo/mix.lock:30`). Initial host should use the researched 2.21.1 behavior and a frozen consumer lock. A single accepted cell does not expand or replace compatibility support.
- **Do not imply AV support from package presence.** The current Cohort Dockerfile installs Bookworm `ffmpeg`; Debian's current Bookworm package is 5.1.9, while `RUNNING.md:27` requires >=6.0. An image tracer can truthfully record AV as unexercised. Phase 138 AV acceptance must probe an actually supported binary/runtime. This is an image-selection check, not authorization for a new dependency/build platform. [Debian package authority](https://packages.debian.org/bookworm/amd64/ffmpeg).
- **Bound negative controls by claim.** Essential families are source/artifact contamination, wrong/missing receipt expectations, simulated/manual retry or duplicate stimulus, failed/unknown cleanup, namespace decoy preservation, and exported-secret canaries. Most can be cheap fixture/validator tests; do not boot the whole stack for each malformed JSON variant. One observed real retry/restart run establishes runtime behavior; no 25-seed or ten-run speed target transfers from Phase 136.
- **Keep the validator's trust limit explicit.** It can reject contradictions, stale identities and changed artifacts. It cannot authenticate a wholly fabricated, internally consistent observation set written by the same trusted collector. No signatures, spent-source registry, witness chain or bespoke authorization machinery should be introduced to chase that unrelated threat.

## Already good

- Dedicated external Phoenix host fits the adopter story and isolates production queue semantics from Cohort's inline/manual/Sandbox test conveniences.
- Exact tar consumption plus clean compilation addresses a real limitation in the current generated proof without rewriting its historical receipts.
- Storage-delete fail-once is a documented seam with useful durable-state behavior. The foundational restart-after-ack avoids introducing Lifeline/orphan rescue only to shorten the test.
- Public detach ingress, unchanged persisted job ID, actual errors/attempts and independent MinIO observation distinguish a job retry from a transport retry or second request.
- Domain cleanup and infrastructure disposal are separate facts; completed history and infrastructure baseline are explicit rather than hidden exceptions.
- Existing Jason, finite scenario predicates, concise safe CLI output and a small janitor are enough. No frontend, new product seam, generic fault DSL or additional release authority is needed.
- Phase 138 retains ownership of all six recovery scenarios; Phase 139 retains aggregate exact-head/remote readiness. The independent-adopter gate remains open.
