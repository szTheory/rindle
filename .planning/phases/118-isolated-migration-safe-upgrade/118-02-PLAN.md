<objective>
Add the bounded populated-upgrade path: classify the complete database state before mutation, then move the fixed seven-relation V1 set from `public` to `rindle` inside the host migration transaction without losing relational state.

Purpose: Give legacy adopters a data-preserving upgrade primitive without turning Rindle into a generic schema manager.
Output: Directional public API, V1 preflight/state machine, fixed forward move, and live PostgreSQL integrity proof.
</objective>

## Trust Boundaries

| Boundary | Description |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-118-04 | Tampering | Catalog preflight | critical | mitigate | Capture and classify all seven fixed relations, marker, ownership, and privileges before the first ALTER; refuse mixed/partial states. |
| T-118-05 | Elevation of Privilege | Dynamic identifiers | high | mitigate | Accept no source/target input; interpolate only fixed `public`/`rindle` and V1-owned names through the quoting boundary; use no `search_path`. |
| T-118-06 | Tampering / Information Disclosure | Host relations | high | mitigate | Assert `oban_jobs` and `schema_migrations` location/content before and after; no production enumeration or DDL targets them. |
| T-118-07 | Repudiation | Bounded failures | medium | mitigate | Errors state observed classification and one corrective action before mutation, enabling operator audit without dumping arbitrary catalog data. |
| T-118-SC | Tampering | package installs | high | mitigate | No install is planned; any new package requires a legitimacy audit and blocking human verification. |
</threat_model>
