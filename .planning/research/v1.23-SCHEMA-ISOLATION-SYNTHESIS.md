# v1.23 Postgres Schema Isolation — Research Synthesis

**Date:** 2026-08-08
**Decision context:** Rindle 0.4.0 makes `rindle` the default Postgres schema for
Rindle-owned state while preserving an explicit `public` compatibility route. It is a
host-app-respectfulness milestone, not a tenancy, media-feature, or Oban milestone.

## Recommended Boundary

- Rindle owns exactly its six domain tables plus `rindle_migration_versions`; fresh
  installs provision them in `rindle`.
- `oban_jobs`, the host's `schema_migrations` ledger, and application tables remain
  host-owned. Rindle's default must not move, create, or configure Oban tables.
- Existing public installs choose explicitly: keep `prefix: "public"`, or run a
  documented host migration that moves only Rindle-owned tables and the marker table.
- Do not use connection `search_path`, automatic data-copy/dual-write migration,
  per-tenant schema management, or a generic schema-management CLI.

## Architecture Decision to Prove First

The existing ISO23 notes proposed a `Rindle.Schema` macro over six Ecto schemas.
That automatically covers normal schema-backed queries but makes an `@schema_prefix`
compile-time decision. Rindle's current `Config.rindle_prefix/0` is runtime-resolved.
The first phase must decide and prove one coherent model:

1. compile-time prefix configuration plus a schema macro, with docs spelling out the
   compile/release contract; or
2. runtime per-query/per-Multi routing through a single internal helper.

The chosen model must preserve the public `rindle` default and explicit `public`
escape hatch, cover new structs/Multi callbacks/background work, and not permit
silent fallback to `public`. Do not mix both models casually.

## Research Findings

- Ecto query/Repo prefixes are deterministic and preferred to `search_path`; schema
  module prefixes are compile-time. Explicit query prefix overrides schema prefix.
  [Ecto.Query](https://hexdocs.pm/ecto/Ecto.Query.html#module-query-prefix)
- Every `Ecto.Multi` operation/callback needs deliberate prefix behavior; transaction
  options do not guarantee propagation. Newly built structs also require routing.
  [Ecto.Repo](https://hexdocs.pm/ecto/Ecto.Repo.html)
- `ALTER TABLE ... SET SCHEMA` preserves a table and its dependent indexes,
  constraints, and owned sequences, but normally needs an exclusive lock. The move
  must fail loudly on mixed/partial state rather than guess.
  [PostgreSQL ALTER TABLE](https://www.postgresql.org/docs/current/sql-altertable.html)
- Dynamic SQL identifiers cannot be query parameters. Validate schema identifiers
  and route DDL through one tested identifier-quoting boundary; use bound values for
  catalog queries. Avoid `search_path` due to its trusted-namespace implications.
  [PostgreSQL schemas](https://www.postgresql.org/docs/current/ddl-schemas.html)
- Oban's prefix is its host configuration concern. Its job table must continue to
  resolve independently from Rindle state.

## Sibling-Library Lessons

- **Sigra:** explicit migration `prefix:` plus `@schema_prefix` and a first-class
  generator contract; never rely on `search_path`.
- **Mailglass:** an internal repo-prefix choke point, explicit per-Multi opts,
  validated <=63-byte identifiers, and a data-preserving move migration; dynamic
  function/trigger SQL is re-created after moves when applicable.
- **Chimeway:** separate Rindle-like product prefix from Oban's prefix; documented
  preflight, maintenance window, schema-qualified verification, and rollback.

Rindle does not own triggers/functions today, so their recreation is not in scope
unless code inspection finds a Rindle-owned database object that needs it.

## Acceptance-Proof Matrix

1. Fresh generated host: `rindle` exists; all Rindle tables and marker exist there;
   no Rindle table or `oban_jobs` is created in the wrong schema.
2. Public compatibility: a deliberate `public` configuration and migration still
   work without changed callers.
3. Real upgrade: populated public Rindle tables plus marker move to `rindle`, retain
   rows/FKs/indexes, and leave `public.oban_jobs` and host `schema_migrations` alone.
4. Runtime routing: facade, worker, maintenance, admin, doctor, and runtime-status
   paths read/write the configured schema; a decoy public table does not mask a miss.
5. Operational truth: doctor/runtime status identify expected versus found prefix and
   give bounded setup/mismatch guidance.
6. Consumer truth: packed-artifact generated-app smoke, Cohort provisioning, docs
   parity, and the existing release/proof lanes cover the 0.4.0 contract.

## Explicitly Deferred

Force-delete (LIFE-06), second streaming provider (STREAM-10), transforms, EXIF
stripping, arbitrary schemas/tenant provisioning, changing Oban's prefix, and a
generic schema manager remain outside v1.23.
